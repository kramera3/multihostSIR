## 1. Why multi-host models

Many wildlife and zoonotic pathogens circulate in several host species at once:
SARS-CoV-2, highly pathogenic avian influenza, rabies, bovine tuberculosis. A
single-host SIR model cannot represent the three features that usually dominate
such systems:

- transmission that is **asymmetric** between species,
- contact structure imposed by the **food web**,
- species-specific **susceptibility and virulence**.

`multihostSIR` handles all three, and derives parameters from body mass whenever
empirical values are unavailable.

---

## 2. The three building blocks

Every simulation is assembled from three objects. Each has sensible defaults and
each prints itself, so you can inspect what a run will do before starting it.

```r
library(multihostSIR)

allo   <- allometry()
spec   <- community_spec()
coeffs <- trophic_coefficients()

allo
spec
```

### `allometry()` - body-mass power laws

Rates follow `Y = a * M^b` where `M` is body mass in kg. Time step is one day
throughout.

| Symbol | Meaning | Default | Rationale |
|---|---|---|---|
| mu | background mortality (day^-1) | `0.005 * M^-0.25` | Quarter-power scaling of physiological rates and lifespan - large animals live longer (Kleiber 1932; Peters 1983). |
| gamma | recovery rate (day^-1) | `0.1 * M^-0.25` | Process *durations* scale as `M^0.25`, so *rates* scale as `M^-0.25` - large animals recover more slowly (Lindstedt & Calder 1981). |
| N | carrying-capacity density (ind km^-2) | `500 * M^-0.75` | Damuth's law - large animals are rarer (Damuth 1981). |
| alpha | disease-induced mortality (day^-1) | `0.01 * M^-0.25` | Quarter-power scaling. |

Worked example, a 0.02 kg host against a 50 kg host:

```
mu    : 0.0133 /day    vs  0.0019 /day
gamma : 0.266  /day    vs  0.038  /day
N     : 9403 ind/km2   vs  26.6 ind/km2
alpha : 0.0266 /day    vs  0.0038 /day
```

```r
plot_allometry(allo)
```

### `community_spec()` - assembly rules

Controls how a random community is drawn:

- `prey_prob` - probability a species is prey (default 0.8)
- `prey_masses`, `predator_masses` - body-mass pools to sample from
- `predator_density_factor` - predator densities are multiplied by this after
  allometric scaling, representing top-down thinning (default 0.1)
- `competence_ranges` - beta ranges per competence category
- `competence_log_scale` - sample competence uniformly on the log scale
  (default `TRUE`), which spreads draws evenly across orders of magnitude

### `trophic_coefficients()` - transmission routes

Row = recipient, column = source:

|  | <- Prey | <- Predator |
|---|---|---|
| **Prey** | 0.50 | 0.00 (blocked) |
| **Predator** | 0.25 | 0.25 |

## 3. Building one community

```r
set.seed(42)
comm <- build_community(6, spec = spec, allo = allo)
comm[, c("species", "type", "mass", "mu", "gamma", "N", "competence")]
```

You get one row per species with columns: `species`, `type`, `mass`,
`trophic_weight`, `mu`, `gamma`, `alpha`, `N`, `competence_category`,
`competence`, `beta_ii`.

---

## 4. Transmission structure

```r
beta <- transmission_matrix(comm)
round(beta, 6)
```

Diagonal entries are within-species rates `beta_ii = competence_i / N_i`.
Off-diagonal entries are the geometric mean `sqrt(beta_ii * beta_jj)` scaled by
a trophic coefficient. **Rows receive infection; columns are the source.**

Under the defaults, predators contract infection from prey but never transmit
back:

```r
beta[comm$type == "Prey", comm$type == "Predator"]   # all zero
plot_transmission_matrix(comm)
```

---

## 5. Community R0

The next-generation matrix is

```
K[i,j] = beta[i,j] * N[i] * D[j],    D[j] = 1 / (gamma_j + mu_j + alpha_j)
```

so `K[i,j]` is the expected number of species-*i* infections generated by one
infected individual of species *j* in an otherwise susceptible community.
Community R0 is its dominant eigenvalue.

```r
community_R0(comm, beta)
next_generation_matrix(comm, beta)
```

**A subtlety worth knowing:** R0 is *invariant* when every species' density is
scaled by the same factor. Because `beta_ii = competence / N` falls as `1/N`
while `K` carries a factor of `N`, the two cancel. Density differences between
species still matter; a uniform rescaling does not.

## 6. Simulating one epidemic

```r
sim <- simulate_epidemic(comm, beta = beta, duration = 365)
species_metrics(sim)
```

By default the epidemic is seeded with one infected individual in the most
competent host. Pass an integer to `seed_species` to choose a different one.

`sim$out` is the full solution: columns `time`, then `S1..Sn`, `I1..In`,
`R1..Rn`, `C1..Cn`. Compartments are addressed **by name**, so your own analysis
code will not break if column ordering ever changes.

`species_metrics()` returns per species: `peak_infected`, `days_to_peak`,
`cum_infected`, `attack_rate`.

## 7. Replicate studies

`run_multihost_sir()` is the main entry point.

```r
res <- run_multihost_sir(
  richness_levels = 3:8,
  n_iterations    = 200,
  duration        = 365,
  seed            = 42
)

res
summary(res)
```

It returns a list with:

- `results` - one row per iteration
- `trajectories` - mean daily prevalence per richness level
- `timing` - elapsed time per richness level
- `settings`, `call`

Figures:

```r
plot_r0_richness(res)
plot_peak_prevalence(res)
plot_trajectories(res, xlim = c(0, 120))
plot_timing(res)
```

Derived tables:

```r
predator_summary(res)
competence_summary(res)
```

For production runs, enable parallel execution:

```r
big <- run_multihost_sir(
  richness_levels = 3:30,
  n_iterations    = 10000,
  seed            = 42,
  parallel        = TRUE,
  n_cores         = parallel::detectCores() - 1,
  progress        = TRUE
)
```

`parallel` defaults to `FALSE` and `n_cores` to `2`, because CRAN checks forbid
using more than two cores. Raise both on your own machine.

## 8. Run-time scaling

Each richness level is timed separately, which supports a scaling study.

```r
cx <- timing_complexity(res)
cx$exponent_richness    # p, where time ~ richness^p
cx$r_squared_richness

plot_timing(res, log_scale = TRUE)
```

The n x n matrix-vector product in the force-of-infection term and the n x n
eigendecomposition used for R0 make an exponent between 2 and 3 the expectation
at large n.

A short **untimed warm-up batch** runs before the timed loop, so one-off costs
(JIT compilation, cluster start-up) do not inflate the first level and distort
the fitted curve. Disable with `warmup = FALSE`.

## 9. Reproducibility

Both execution modes are seed-reproducible:

```r
a <- run_multihost_sir(3:5, n_iterations = 50, seed = 42)
b <- run_multihost_sir(3:5, n_iterations = 50, seed = 42)
identical(a$results$R0, b$results$R0)   # TRUE
```

Serial runs use `set.seed()`; parallel runs use
`parallel::clusterSetRNGStream()`. The seed is applied **after** the warm-up, so
warm-up never perturbs recorded results.

A serial run and a parallel run with the same seed give *different* (but
equally valid) results, because L'Ecuyer streams differ from the default RNG.
Fix `parallel` as well as `seed` when you need bit-identical output.

## 10. Exporting results

```r
export_results(res, dir = "output", formats = c("csv", "xlsx"))
```

Writes `results`, `trajectories`, `timing`, `summary`, `predator` and
`competence` tables. Excel output needs the optional `openxlsx` package; if it
is missing you get a warning and CSV only.

Excel sheets cap at 1,048,576 rows. Larger tables get a pointer note in the
workbook; the complete data always go to CSV regardless.

## 11. Changing the assumptions

Every default is an argument.

```r
custom <- run_multihost_sir(
  richness_levels = 3:5,
  n_iterations    = 100,
  spec = community_spec(
    predator_density_factor = 0.4,      # predators less rare
    prey_masses = c(5, 20, 80)          # larger-bodied prey
  ),
  allo = allometry(a_recovery = 0.05),  # slower recovery
  coefficients = trophic_coefficients(
    pred_to_prey = 0.1                  # unblock predator -> prey
  ),
  seed = 1
)
```

## 12. Model definition

For species *i* in a community of *n* species:

```
dS_i/dt = b_i - mu_i * S_i - Lambda_i * S_i
dI_i/dt = Lambda_i * S_i - (mu_i + gamma_i + alpha_i) * I_i
dR_i/dt = gamma_i * I_i - mu_i * R_i
dC_i/dt = Lambda_i * S_i
```

where `Lambda_i = sum_j beta[i,j] * I_j` is the force of infection and `C_i`
accumulates cumulative incidence without feeding back into the dynamics.

Births `b_i = mu_i * N_i` are held constant, so the disease-free equilibrium is
`S_i = N_i`. **Total population size is not conserved when virulence alpha_i > 0.**
This is a modelling choice, not an oversight: it keeps the disease-free state
fixed at the allometric carrying capacity while allowing disease-induced
mortality to reduce standing abundance.

A discrete event fires at each integer time step and sets any infected
compartment holding fewer than one individual to exactly zero. Without it,
floating-point residues on the order of 10^-15 individuals sustain phantom
transmission indefinitely. Set `extinction_threshold = 0` to disable.

## 13. Troubleshooting

**`there is no package called 'deSolve'`**
Run `install_dependencies()`, or `source("install.R")` from the repository root.

**`check_dependencies()` reports something OUTDATED**
Run `install_dependencies(ask = FALSE)`.

**Excel export does nothing**
`openxlsx` is optional. Install it with `install.packages("openxlsx")`, or use
`formats = "csv"`.

**Parallel runs are slower than serial**
Cluster start-up costs roughly a second. For small `n_iterations` or short
`duration`, serial wins. Parallelism pays off from a few hundred iterations
upward.

**Parallel runs fail on Windows**
PSOCK workers load the package fresh. Make sure `multihostSIR` is installed in a
library the workers can see, not merely loaded with `devtools::load_all()`.

**Results differ between machines**
Check that `seed` *and* `parallel` match. Different core counts change how
L'Ecuyer streams are allocated, so `n_cores` must match too for bit-identical
parallel output.

**`R0` is `NaN` or `Inf`**
Usually a species with a density at or near zero, which makes
`beta_ii = competence / N` blow up. Check `predator_density_factor` is not
effectively zero, and that all body masses are positive.
